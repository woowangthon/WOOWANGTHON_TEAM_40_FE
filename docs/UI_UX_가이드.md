# UI와 UX 디자인 가이드

이 문서는 학습 도우미 화면을 만들면서 정한 디자인 기준을 서비스 종류와 무관하게 다시 쓸 수 있도록 정리한 것이다. 특정 화면을 다시 만드는 설명서가 아니라, 어떤 웹 서비스를 만들든 같은 수준의 결과물이 나오게 하는 원칙과 수치와 점검 절차를 담는다. 사람에게 건네도 되고 AI에게 그대로 건네도 된다.

기준은 세 갈래에서 왔다. 첫째는 사용자가 여러 차례 검토하며 준 요구이고, 둘째는 대형 서비스의 공개 디자인 문서 다섯 곳이며, 셋째는 접근성 표준과 브랜드 사용 안내다. 2026년 11월 12일에 확인한 내용이다.

## 1. 한 문장 요약

흰색 또는 짙은 회색 바탕에 무채색과 강조색 하나만으로, 테두리와 명암으로 구조를 드러내고, 상태는 점과 글자로만 알리며, 설명 문장 없이도 쓸 수 있을 만큼 화면을 잘게 나눈다.

## 2. 사용자가 요구한 것

아래는 실제 검토에서 나온 요구를 원칙으로 바꾼 것이다. 이 목록이 다른 모든 기준보다 앞선다.

| 요구 | 원칙으로 바꾼 것 |
|---|---|
| 생성형 AI가 만든 티가 나는 둥글둥글한 화면이 싫다 | 알약 모양 배지, 색이 든 둥근 상자, 큰 숫자 카드, 그림자 위주의 카드 쌓기를 쓰지 않는다 |
| 큰 글씨 아래에 작은 회색 글씨를 붙이는 구성이 싫다 | 제목 아래 부제와 도움말 문장을 두지 않는다. 이름과 값을 한 줄에 나란히 놓는다 |
| 가운뎃점과 특수기호를 쓰지 않는다 | 화면 글자에 가운뎃점, 화살표, 괄호, 이모지를 쓰지 않는다. 낱말과 칸 나눔으로 구분한다 |
| 모서리를 덜 둥글게 한다 | 모서리 반지름은 5에서 6픽셀을 기본으로 한다 |
| 색은 절제한다 | 무채색에 강조색 하나, 경고색 하나를 기본으로 한다. 뜻을 구분해야 할 때만 색을 더한다 |
| 한 화면에 반 전체와 개인 기록이 섞여 불편하다 | 한 화면은 한 가지 질문에만 답하게 하고 하위 페이지로 나눈다 |
| 정지된 그림이 아니라 실제로 동작해야 한다 | 화면이 열릴 때 막대가 0에서 값만큼 자라는 식으로 값의 변화를 움직임으로 보여 준다 |
| 대비가 약해 구분이 안 된다 | 글자와 선과 바탕의 대비를 수치로 계산해 기준을 넘긴다 |
| 다크 모드가 너무 어둡다 | 다크 바탕은 검정이 아니라 짙은 회색으로 한다 |
| 사이드바와 본문이 구분되지 않는다 | 사이드 영역은 본문과 같은 계열에서 한 단계 어둡게 한다 |
| 메뉴 글자 왼쪽에 작은 아이콘이 있어야 읽기 쉽다 | 메뉴, 탭, 목록 줄의 이름 왼쪽에 외곽선 아이콘을 둔다 |
| 고를 것은 버튼처럼 보이고 예시가 들어 있어야 한다 | 선택지는 예시 미리보기가 든 상자로 만들고 누르면 고른 상태가 테두리로 드러난다 |
| 덕지덕지 붙이지 않는다 | 같은 기능으로 가는 버튼을 한 화면에 여러 개 두지 않는다. 요소를 더하기 전에 뺄 것을 먼저 찾는다 |

## 3. 참고한 출처와 가져온 것

| 출처 | 가져온 기준 |
|---|---|
| Vercel Geist | 상태는 점과 글자로 표시하고 한 줄에 상태 표시는 하나만 둔다. 색만으로 뜻을 전하지 않는다. 이름과 값은 두 칸짜리 표가 아니라 설명 목록으로 보여 준다. 탭은 한 페이지 안의 형제 화면을 바꿀 때 쓰고 다섯 개에서 일곱 개까지 둔다 |
| GitHub Primer | 숫자는 오른쪽 정렬하고 자릿수 폭이 같은 숫자 글꼴 설정을 쓴다. 메뉴의 앞쪽 아이콘은 모든 항목에 붙이거나 모두 뺀다. 아이콘은 16픽셀에 1.5픽셀 외곽선이다. 옅은 바탕을 쓰면 테두리를 더해 대비를 올린다. 탭을 두 단계보다 깊게 겹치지 않는다. 보기 방식 전환은 두 개에서 다섯 개짜리 구획 버튼으로 한다 |
| Atlassian Design System | 버튼과 입력의 모서리는 6픽셀이다. 24픽셀보다 작은 글자는 4.5 대 1, 화면 이해에 필요한 요소는 3 대 1 대비를 넘긴다. 가라앉은 면은 두 모드 모두에서 더 어둡다. 다크에서는 높이 있는 면일수록 밝게 한다. 아이콘은 글자와 함께 쓰고 꼭 필요하지 않으면 뺀다. 같이 봐야 하는 정보를 탭으로 가르지 않는다 |
| Stripe Apps | 작업 영역을 주소에 묶인 탭으로 나눈다. 상세 화면은 별도 주소로 두고 경로 표시로 돌아간다. 먼저 전체 개요를 보여 주고 한꺼번에 모든 정보를 쏟지 않는다 |
| Linear 디자인 글 | 시각적 잡음을 줄인다. 사이드바를 한 단계 어둡게 낮춰 본문이 앞서게 한다. 구분선의 수와 대비를 줄이고 아이콘의 수와 크기를 줄인다. 테마를 바탕색, 강조색, 대비 세 값으로 다룬다 |

보조로 쓴 기준은 다음과 같다. W3C의 캐러셀 안내와 WCAG 2.2.2는 자동으로 움직이는 내용에 멈춤 수단을 요구한다. Material 3은 사용자 입력 없이 넘어가는 배경 전환에 1초를 쓴다. Google 브랜드 안내는 Google 로그인 버튼의 문구와 바탕색과 테두리색을 정한다.

## 4. 색

### 4.1 토큰

색은 모두 CSS 변수로 두고 화면 코드에는 색 값을 직접 쓰지 않는다. 라이트와 다크는 같은 이름에 다른 값을 준다.

| 이름 | 쓰임 | 라이트 | 다크 |
|---|---|---|---|
| `--bg` | 본문 바탕 | `#ffffff` | `#26282c` |
| `--bg-side` | 사이드 영역 바탕 | `#f1f3f6` | `#1c1e21` |
| `--bg-2` | 표 머리와 미리보기 바탕 | `#f3f5f8` | `#2d3034` |
| `--bg-hover` | 본문 위 올림 바탕 | `#e8ebf0` | `#363a3f` |
| `--side-hover` | 사이드 영역 위 올림 바탕 | `#e5e8ed` | `#282a2e` |
| `--side-active` | 사이드 영역의 선택 바탕 | `#d9dee6` | `#33363b` |
| `--field` | 입력란과 버튼 바탕 | `#ffffff` | `#303338` |
| `--track` | 막대의 빈 자리 | `#e1e5eb` | `#3b3e44` |
| `--line` | 안쪽 구분선 | `#d6dae1` | `#3e4147` |
| `--line-2` | 묶음과 버튼의 테두리 | `#b8bfc9` | `#555a62` |
| `--line-3` | 입력란 테두리 | `#848c99` | `#848b96` |
| `--text` | 본문 글자 | `#101318` | `#f2f3f5` |
| `--text-2` | 보조 글자와 표 머리 | `#454d59` | `#bdc2ca` |
| `--text-3` | 자리 표시 글자와 흐린 아이콘 | `#636b78` | `#9aa0aa` |
| `--accent` | 주 버튼 바탕 | `#2563eb` | `#3b6ee6` |
| `--accent-press` | 주 버튼의 올림 상태 | `#1d4fc4` | `#2f5fd0` |
| `--accent-ink` | 링크 글자 | `#1d4ed8` | `#93b4ff` |
| `--accent-bar` | 막대, 선택 테두리, 진행 중 점 | `#2f6fed` | `#6a96f8` |
| `--alert` | 경고와 틀린 부분 | `#c0271d` | `#ff8171` |
| `--mute` | 차트의 비교 대상 | `#b9c0cb` | `#5c616b` |

강조색을 바꾸고 싶으면 `--accent` 계열 네 값만 바꾼다. 바꾼 뒤에는 4.3의 대비 기준을 다시 계산한다.

### 4.2 영역별 명암

- 본문은 `--bg`, 왼쪽 사이드바와 오른쪽 보조 영역과 위쪽 내비게이션 띠는 `--bg-side` 를 쓴다. 사이드 영역이 두 모드 모두에서 본문보다 어둡다.
- 두 면의 대비는 1.1 대 1 정도로 작게 두고 경계에 `--line` 한 줄을 더한다. 명암 차이를 크게 벌려 구분하지 않는다.
- 다크에서 깊이는 그림자가 아니라 더 밝은 면으로 표현한다. 사이드 영역 위에 놓는 카드는 `--bg` 를, 본문 위의 입력란은 `--field` 를 쓴다.
- 다크 바탕은 검정을 쓰지 않는다. 본문은 `#26282c` 정도의 짙은 회색이다.

### 4.3 대비 기준

아래 수치를 넘지 못하면 색을 다시 고른다. 계산은 WCAG의 상대 휘도 공식으로 한다.

| 대상 | 기준 | 이 토큰의 값 |
|---|---|---|
| 본문 글자와 바탕 | 4.5 대 1 이상 | 라이트 18.6, 다크 13.3 |
| 가장 옅은 글자와 가장 어두운 바탕 | 4.5 대 1 이상 | 라이트 4.8, 다크 5.6 |
| 주 버튼의 글자와 바탕 | 4.5 대 1 이상 | 라이트 5.2, 다크 4.6 |
| 입력란 테두리와 바탕 | 3 대 1 이상 | 라이트 3.4, 다크 3.7 |
| 묶음 테두리 | 1.5에서 2.2 대 1 | 라이트 1.9, 다크 2.1 |
| 안쪽 구분선 | 1.2에서 1.5 대 1 | 라이트 1.4, 다크 1.4 |

구분선은 일부러 약하게 두고, 조작해야 하는 입력란의 테두리만 3 대 1을 넘긴다. 모든 선을 진하게 하면 구조가 아니라 선이 먼저 보인다.

### 4.4 색을 더 쓸 때

뜻을 구분해야 해서 색을 더할 때는 세 가지를 지킨다. 색마다 이름 글자를 함께 붙인다. 넓은 면을 칠하지 않고 4픽셀 세로 막대나 밑줄 같은 작은 표시로 쓴다. 범례를 그 영역 위에 둔다. 예를 들어 채점 근거의 출처를 구분할 때 교수 채점 기준은 갈색, 학습 자료는 청록, AI 판단은 파랑으로 세로 막대를 긋고 출처 이름을 같은 색 글자로 적었다. AI를 나타내는 색으로 보라색을 쓰지 않고 반짝이 아이콘도 쓰지 않는다.

## 5. 글자

- 글꼴은 한 가지만 쓴다. 한글 서비스는 Pretendard를 쓰고 코드와 식별자에만 고정폭 글꼴을 쓴다.
- 기본 크기는 14픽셀, 줄 높이는 1.5다. 화면 제목은 20픽셀에 굵기 650, 구역 제목은 15픽셀에 굵기 600, 표 머리는 13픽셀에 굵기 500이다.
- 위계는 크기보다 굵기와 간격으로 만든다. 한 화면에서 쓰는 크기는 네 가지를 넘기지 않는다.
- 숫자는 자릿수 폭이 같은 설정을 켜고 표에서는 오른쪽에 맞춘다.
- 값을 강조하려고 숫자를 크게 키우지 않는다. 이름은 보조 글자색, 값은 본문 글자색에 굵기 600으로 같은 줄에 둔다.

## 6. 간격과 모양

| 항목 | 값 |
|---|---|
| 모서리 반지름 | 버튼과 입력 5픽셀, 묶음과 카드 6픽셀 |
| 테두리 두께 | 1픽셀 |
| 버튼 높이 | 32픽셀, 큰 버튼 38픽셀 |
| 입력란 높이 | 34픽셀 |
| 표의 줄 높이 | 머리 36픽셀, 본문 44픽셀 |
| 목록 줄 높이 | 46픽셀 이상, 안쪽 여백 좌우 16픽셀 |
| 사이드바 | 너비 232픽셀, 항목 높이 32픽셀 |
| 본문 | 최대 너비 1120픽셀, 좁은 화면용 880픽셀, 좌우 여백 40픽셀 |
| 구역 사이 | 36픽셀 |
| 글자와 묶음 가장자리 | 12픽셀 이상 |

그림자는 기본 화면에 쓰지 않는다. 면을 구분하는 수단은 테두리와 바탕색이다.

## 7. 화면 구조

### 7.1 뼈대

- 왼쪽에 사이드바, 오른쪽에 본문을 둔다. 사이드바는 화면 높이에 고정하고 본문만 스크롤한다.
- 사이드바의 내용은 지금 있는 곳에 따라 바뀐다. 목록 화면에서는 거르는 조건이 들어가고, 항목 하나에 들어가면 뒤로 가기와 그 항목의 하위 페이지 목록으로 바뀐다. 사이드바를 두 겹으로 세우지 않는다.
- 한 가지 흐름에 집중해야 하는 화면은 사이드바 대신 위쪽 띠에 단계를 가로로 둔다. 지난 단계는 체크, 지금 단계는 그 단계의 아이콘, 열리지 않은 단계는 자물쇠로 표시한다.
- 너비 960픽셀 아래에서는 사이드바가 위쪽 가로 메뉴로 바뀌고 여러 칸이 한 칸으로 쌓인다.

### 7.2 페이지 나누기

- 한 페이지는 한 가지 질문에 답한다. 전체 현황과 한 사람의 기록처럼 대상이 다르면 페이지를 나눈다.
- 나누는 수단은 깊이에 따라 고른다. 항목이 많거나 계층의 위쪽이면 사이드바 목록, 한 대상 안의 형제 화면이면 밑줄 탭, 정렬과 거르기와 보기 방식 전환이면 구획 버튼이다.
- 탭은 일곱 개를 넘기지 않고 두 단계보다 깊게 겹치지 않는다. 탭과 하위 페이지는 주소에 묶어 새로 고침과 공유가 되게 한다.
- 상세 화면은 별도 주소로 두고 위에 경로 표시를 달아 목록으로 돌아가게 한다.
- 개요 페이지는 지표를 나열하지 않고 다음에 할 일을 보여 준다. 확인이 필요한 항목을 건수와 함께 목록으로 두고 누르면 해당 페이지로 간다. 건수가 0인 항목은 숨긴다.

### 7.3 지표

- 큰 숫자 카드를 쓰지 않는다. 지표는 이름과 값이 한 줄에 놓이는 칸을 가로로 이어 붙인 요약 띠로 보여 준다.
- 비교가 필요한 값은 표나 가로 막대 목록으로 보여 준다. 기준선이 있으면 막대 위에 세로선으로 표시한다.
- 빈 값은 비워 두거나 미응시 같은 낱말로 적는다. 줄표를 채워 넣지 않는다.

| 부품 | 규칙 |
|---|---|
| 상태 표시 | 지름 7픽셀 점과 글자로만 표시한다. 시작 전은 빈 원, 진행 중은 강조색 점, 끝남은 본문 글자색 점, 확인 필요는 경고색 점이다. 한 줄에 하나만 둔다 |
| 버튼 | 주 버튼은 한 화면에 하나다. 나머지는 테두리 버튼과 테두리 없는 조용한 버튼을 쓴다. 같은 일을 하는 버튼을 여러 곳에 두지 않는다 |
| 입력란 | 바탕과 3 대 1 이상인 테두리를 두르고 초점이 들어오면 강조색 테두리와 옅은 고리를 보인다. 모든 입력에 이름표를 단다 |
| 표 | 머리 줄에 옅은 바탕을 깔고 줄 사이에 구분선을 둔다. 줄 전체를 눌러 상세로 가게 하고 올림 바탕으로 누를 수 있음을 알린다 |
| 목록 줄 | 왼쪽에 아이콘과 이름, 가운데에 상태, 오른쪽 끝에 값과 꺾쇠를 둔다 |
| 탭 | 밑줄 탭을 쓰고 선택된 탭은 본문 글자색 2픽셀 밑줄로 표시한다 |
| 카드 | 테두리만 두른 상자다. 위쪽에 내용 종류를 알리는 미리보기 그림, 아래쪽에 아이콘과 제목과 상태 한 줄, 그 아래 진행 막대와 값 한 줄을 둔다 |
| 미리보기 그림 | 실제 글자 없이 막대와 선으로 종류만 알린다. 코드는 짙은 편집기 바탕에 색 막대, 문서는 제목과 문단과 표, 다이어그램은 선으로 이은 상자다. 그림은 위와 좌우에 여백을 두고 아래로 잘려 나가게 놓는다 |
| 선택 상자 | 고를 것이 서로 다른 모양의 결과를 낳으면 예시를 넣은 상자를 나란히 놓는다. 고른 상자는 강조색 테두리로 표시하고 고르면 그에 맞는 입력란이 아래에 열린다 |
| 확인 | 브라우저의 확인 창과 입력 창을 쓰지 않는다. 되돌릴 수 없는 동작은 그 자리에 문장과 취소와 실행 버튼이 든 확인 블록을 연다 |
| 알림 | 저장 결과와 오류는 화면 위쪽의 한 줄 알림으로 보여 주고 닫기 버튼을 둔다. 저장됨은 버튼 옆에 점과 글자로 잠깐 표시한다 |
| 빈 상태 | 묶음 안에 한 문장으로 적는다. 그림을 넣지 않는다 |

## 9. 아이콘

- 한 벌만 쓴다. 이 기준에서는 Lucide를 쓰고 크기 16픽셀, 선 굵기 1.5픽셀, 외곽선 모양으로 통일한다.
- 메뉴, 탭, 단계, 목록 줄, 카드 제목의 이름 왼쪽에 둔다. 한 목록 안에서는 모든 항목에 붙이거나 모두 뺀다.
- 아이콘 색은 흐린 글자색이고 올림과 선택 상태에서 본문 글자색으로 바뀐다.
- 아이콘만 있는 버튼에는 읽어 줄 이름을 붙인다.
- 직접 그린 아이콘과 이모지를 쓰지 않는다. 다른 회사의 마크는 그 회사가 공개한 원본만 쓰고 색과 비율을 바꾸지 않는다.

## 10. 화면 글

- 제목 아래 부제, 구역 아래 설명 문장, 입력란 아래 도움말을 넣지 않는다. 그 문장이 없으면 조작할 수 없는 경우에만 한 문장을 둔다.
- 가운뎃점, 화살표, 괄호, 이모지, 장식 기호를 쓰지 않는다. 날짜는 11월 15일처럼 낱말로 적는다.
- 구분은 칸 나눔과 줄 나눔으로 한다. 한 줄에 여러 정보를 기호로 이어 붙이지 않는다.
- 버튼 글은 동작을 그대로 적는다. 저장, 제출, 게시처럼 한두 낱말이다.
- 이름표와 값은 둘 다 낱말이다. 값이 없으면 줄을 빼거나 낱말로 적는다.

## 11. 움직임

| 대상 | 값 |
|---|---|
| 페이지가 열릴 때 | 6픽셀 아래에서 올라오며 나타난다. 0.28초 |
| 막대와 세로 막대 | 0에서 값까지 자란다. 0.8에서 0.9초, 항목마다 50에서 70밀리초씩 늦춘다 |
| 숫자 | 0에서 값까지 0.7초 동안 올라간다 |
| 올림과 누름 | 0.1에서 0.12초 |
| 감속 곡선 | `cubic-bezier(0.2, 0.7, 0.2, 1)` |
| 자동으로 넘어가는 사진 | 한 장을 8초 유지하고 1초 동안 겹쳐 넘긴다 |

- 움직임은 값이나 상태가 바뀐 것을 알릴 때만 쓴다. 꾸미려고 넣지 않는다.
- 운영체제에서 움직임 줄이기를 켠 사용자에게는 모든 움직임을 끈다. 자동 전환은 시작하지 않는다.
- 자동으로 넘어가는 내용에는 멈춤 버튼을 두고 마우스를 올리거나 키보드 초점이 들어오면 멈춘다.
- 값이 바뀌면 막대의 너비가 0.6초 동안 이어서 변하게 해 무엇이 바뀌었는지 보이게 한다.

## 12. 로그인 화면

- 입력 묶음과 사진을 화면 가운데에 나란히 둔다. 사진은 화면 너비의 삼분의 일 남짓, 높이의 70퍼센트 정도인 상자로 두고 화면 끝까지 채우지 않는다.
- 입력 묶음은 너비 360픽셀이고 서비스 이름, 화면 제목, 입력란, 주 버튼, 가입 링크 순서다.
- 소셜 로그인 버튼은 구분 글자 아래에 둔다. 서버에 설정된 공급자만 보여 주고 동작하지 않는 버튼은 화면에 내지 않는다.
- Google 버튼은 Google 브랜드 안내를 따른다. 밝은 바탕은 `#FFFFFF` 에 테두리 `#747775`, 어두운 바탕은 `#131314` 에 테두리 `#8E918F` 이고 문구는 Google 계정으로 로그인 또는 Google 계정으로 가입이다.
- 사진은 사용 조건이 확인된 것만 쓰고 출처와 사진가와 라이선스와 확인일을 기록한다.

## 13. 접근성

- 대비는 4.3의 수치를 지킨다.
- 색만으로 뜻을 전하지 않는다. 점에는 글자를, 색 막대에는 이름을 붙인다.
- 모든 입력에 이름표를 달고 아이콘 버튼에 이름을 붙인다.
- 키보드 초점은 2픽셀 강조색 외곽선으로 보인다.
- 꾸밈 그림과 아이콘은 읽어 주지 않게 숨긴다.
- 움직이는 내용은 멈출 수 있어야 하고 움직임 줄이기 설정을 따른다.

## 14. 기존 화면과 같이 살기

새 기준을 한 번에 입힐 수 없는 화면이 있으면 그 화면을 감싸는 영역을 정하고, 새 부품 규칙은 그 영역 밖에서만, 예전 규칙은 그 영역 안에서만 적용되게 CSS의 `@scope` 로 나눈다. 색 변수는 전역에 두고 예전 변수 이름을 새 변수에 이어 주면 예전 화면도 새 색과 다크 모드를 따른다. 예전 스타일시트 파일은 고치지 않고 빌드 단계에서 감싸면 다른 사람의 변경과 합칠 때 충돌이 나지 않는다.

## 15. 다른 점검 도구와 어긋날 때

stageshow처럼 제품 화면 삽화를 위한 점검 기준은 실제 서비스 화면과 어긋나는 곳이 있다. 그럴 때는 3장의 출처를 따르고 어떤 문제에서 무엇을 골랐는지 글로 남긴다. 이번에 어긋난 곳은 다음과 같다.

| 문제 | stageshow | 고른 것 |
|---|---|---|
| 테두리 | 색조 차이로 충분하면 뺀다 | 묶음과 사이드바 경계에 테두리를 두고 입력란은 더 진하게 한다 |
| 아이콘 모양 | 14픽셀 이하는 채운 모양을 쓴다 | 모두 16픽셀 외곽선으로 통일한다 |
| 실제 글자 | 글자는 몇 개만 두고 나머지는 회색 막대로 채운다 | 화면에는 실제 내용만 둔다. 막대 채우기는 카드의 미리보기 그림에만 쓴다 |
| 정지 시간 | 어떤 것도 3초 넘게 멈춰 있지 않게 한다 | 자동 전환 사진은 5초를 하한으로 보고 8초 유지한다 |
| 색 수 | 무채색에 강조색 하나로 시작한다 | 뜻을 구분할 때는 이름 글자를 붙인 색을 더 쓴다 |
| 메뉴 항목 바탕 | 링크에 올림 바탕을 주지 않는다 | 사이드바 항목에 올림과 선택 바탕을 둔다 |

## 16. 하지 않는 것

아래 가운데 하나라도 보이면 고친다.

- 색이 든 알약 모양 배지와 색 상자
- 큰 숫자 하나에 작은 회색 이름표가 붙은 통계 카드
- 제목 아래의 회색 부제와 구역마다 달린 설명 문장
- 가운뎃점으로 이어 붙인 정보와 화살표 기호
- 8픽셀이 넘는 모서리와 그림자로 띄운 카드
- 한 화면에 섞인 전체 지표와 개별 기록
- 같은 곳으로 가는 버튼 여러 개
- 뜻 없는 색 구분과 세 가지가 넘는 강조색
- 검정 바탕의 다크 모드와 흐려서 읽히지 않는 구분선
- 직접 그린 아이콘과 이모지와 지어낸 로고
- 브라우저 확인 창
- 동작하지 않는 버튼과 고정된 가짜 결과

## 17. 작업 순서

1. 화면마다 답해야 할 질문을 한 문장으로 적고, 질문이 둘이면 페이지를 나눈다.
2. 사이드바와 탭과 구획 버튼 가운데 무엇으로 나눌지 7.2의 기준으로 정하고 주소를 정한다.
3. 색 토큰을 먼저 넣고 4.3의 대비를 계산한다.
4. 뼈대와 공용 부품을 만든다. 상태 표시, 요약 띠, 표, 목록 줄, 막대, 알림, 확인 블록이다.
5. 실제 자료로 화면을 채운다. 자료가 없는 요소는 만들지 않는다.
6. 16장의 목록으로 걸러 낸다.
7. 라이트와 다크, 넓은 화면과 좁은 화면을 각각 캡처해 눈으로 확인한다.
8. 다른 점검 도구와 어긋난 곳은 15장의 방식으로 기록한다.

## 18. 완료 기준

- 화면 코드에 색 값이 직접 적혀 있지 않다.
- 4.3의 대비 수치를 계산한 결과가 남아 있다.
- 16장의 항목이 화면에 하나도 없다.
- 모든 입력에 이름표가 있고 키보드만으로 조작된다.
- 라이트와 다크 캡처를 모두 확인했다.
- 움직임 줄이기를 켰을 때 움직임이 멈춘다.
- 쓴 글꼴, 아이콘, 사진, 마크의 출처와 라이선스를 적었다.
