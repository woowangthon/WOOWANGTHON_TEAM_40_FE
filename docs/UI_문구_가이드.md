# 화면 문구 가이드

웹 화면을 만들 때 AI가 쓴 티가 나는 문구를 없애기 위한 규칙이다. 특정 서비스에 묶이지 않으며 어떤 프로젝트의 화면에도 그대로 적용한다. 화면을 새로 만들 때와 이미 만든 화면을 검수할 때 모두 이 문서를 기준으로 삼는다.

## 1. 한 문장 요약

실제로 운영하는 서비스의 화면에는 요소마다 설명이 붙어 있지 않다. 설명은 소개 화면과 홈에만 두고, 그 밖의 화면에는 이름과 값과 버튼만 둔다.

## 2. 왜 이 규칙이 필요한가

AI는 화면을 만들 때 제목마다 부제를 달고, 카드마다 꼬리표를 붙이고, 기능마다 동작을 설명하는 문장을 넣는 버릇이 있다. 하나하나는 친절해 보이지만 모이면 화면이 설명서처럼 읽히고 시제품처럼 보인다. 사용자는 설명을 읽으러 온 것이 아니라 일을 하러 왔다. 이름이 분명하면 설명은 필요 없고, 설명이 필요하다면 이름이나 배치가 잘못된 것이다.

## 3. 설명을 둘 수 있는 곳과 없는 곳

| 위치 | 설명 문장 |
|---|---|
| 소개 화면, 홈의 첫 구역 | 둔다. 서비스가 무엇인지 말하는 자리다 |
| 도움말, 정책 문서, 약관 | 둔다. 읽으려고 여는 문서다 |
| 처음 한 번 보는 안내, 동의 화면 | 둔다. 사용자가 알고 동의해야 하는 내용만 |
| 빈 상태 | 한 줄만 둔다. 무엇이 없는지만 말한다 |
| 그 밖의 모든 화면 요소 | 두지 않는다. 제목, 카드, 표, 입력 칸, 버튼, 패널 모두 |

## 4. 지우는 것

아래에 해당하는 문구는 문구만 지우지 않고 그 문구를 담던 요소까지 지운다.

| 종류 | 예 | 처리 |
|---|---|---|
| 제목 아래의 부제 | 과제 현황 아래의 반 전체 진행 상황을 한눈에 본다 | 지운다 |
| 제목 옆의 꼬리표 | 실행 환경 옆의 교수 지정, 사전평가 옆의 2번 단답형 | 지운다 |
| 동작 설명 | 저장할 때마다 버전이 남는다, 처음에는 몇 분 걸린다 | 지운다 |
| 조작 안내 | Enter 로 보낸다, 끌어서 순서를 바꾼다 | 지운다. 표준 조작은 설명하지 않는다 |
| 같은 말 반복 | 제목이 학습 자료인데 아래에 학습에 쓰는 자료다 | 지운다 |
| 장식 배지 | 권장, 서비스 표준, 새 기능 | 지운다. 실제 제약을 나타내는 것만 남긴다 |
| 꾸미는 말 | 간편하게, 손쉽게, 강력한, 한눈에 | 지운다 |
| 격려와 인사 | 잘하고 있다, 환영한다, 시작해 볼까 | 지운다 |
| 개발자 메모 | 준비 중이다, 다른 사람이 구현한다, 내부 단계 번호 | 지운다 |
| 색으로 이미 알리는 것을 글로 다시 쓰기 | 색 범례가 있는데 항목마다 출처 이름을 다시 적기 | 색만 남긴다 |
| 시작하기, 자세히 보기 같은 구역별 이동 링크 | 구역마다 붙은 시작하기 | 지운다. 이동은 메뉴와 맨 끝의 버튼 하나로 한다 |

## 5. 남기는 것

- 입력 칸의 이름, 버튼 이름, 탭과 메뉴 이름, 표의 머리
- 값과 상태. 실제 자료에서 온 숫자, 날짜, 남은 시간, 진행 상태
- 오류와 검증 안내. 무엇이 틀렸고 어떻게 고치는지
- 되돌릴 수 없는 일의 확인
- 사용자가 알아야 안전한 고지. 기록 범위, AI의 한계, 개인정보
- 실제 제약을 나타내는 표시. 필수, 읽기 전용, 마감 지남

지울지 남길지 애매하면 이렇게 판단한다. 그 문구를 지웠을 때 사용자가 할 수 있는 일이 줄어들거나 숫자의 뜻을 알 수 없게 되면 남긴다. 아무 일도 일어나지 않으면 지운다.

## 6. 단어를 고르는 법

### 긴 이름은 명사 하나로 줄인다

누가 무엇을 했는지 풀어 쓴 이름은 화면의 자리가 이미 말해 주는 내용을 반복한다.

| 쓰지 않는다 | 쓴다 |
|---|---|
| 교수가 안내한 규칙 | 규칙 |
| 사전평가에서 틀린 문항 | 틀린 문항 |
| 내가 제출한 결과물 목록 | 제출물 |
| 교수가 올린 학습 자료 | 학습 자료 |
| AI와 나눈 대화 기록 | 대화 |

### 문장으로 된 상태는 상태어로 바꾼다

값이 들어갈 자리에 문장을 넣지 않는다. 짧은 상태어 하나로 쓴다.

| 쓰지 않는다 | 쓴다 |
|---|---|
| 쓰지 않았다, 입력하지 않았다 | 미입력 |
| 아직 제출하지 않았다 | 미제출 |
| 아직 응시하지 않았다 | 미응시 |
| 정하지 않았다, 설정되어 있지 않다 | 없음 |
| 채점하고 있다 | 채점 중 |
| 기다리고 있다 | 대기 |
| 모두 끝났다 | 완료 |

같은 뜻에는 화면 전체에서 같은 상태어를 쓴다. 한 곳에서 미입력이라고 썼으면 다른 곳에서 비어 있음이라고 쓰지 않는다.

### 버튼은 동작 이름만 쓴다

| 쓰지 않는다 | 쓴다 |
|---|---|
| 변경 사항 저장하기 | 저장 |
| 지금 바로 제출하기 | 제출 |
| 새로운 과제 만들어 보기 | 과제 만들기 |
| 확인했습니다 | 확인 |

### 빈 상태는 무엇이 없는지만 말한다

| 쓰지 않는다 | 쓴다 |
|---|---|
| 아직 등록된 자료가 없다. 위의 버튼을 눌러 첫 자료를 올려 보자 | 자료 없음 |
| 대화를 시작하면 여기에 내용이 표시된다 | 대화 없음 |

다음에 할 일이 화면에서 바로 보이지 않을 때만 한 줄을 더한다.

## 7. 글 대신 쓸 수 있는 것

설명 문장을 지우고 나서 정보가 모자라면 글을 다시 넣지 말고 아래 방법을 먼저 쓴다.

- **색**: 종류나 출처는 색으로 구분하고 범례는 한 번만 둔다. 예를 들어 틀린 부분을 표시할 때 근거의 출처 이름을 항목마다 적지 않고, 표시 자체를 출처의 색으로 칠한다.
- **자리**: 관련된 것을 가까이 두고 순서로 흐름을 보인다.
- **아이콘**: 메뉴와 버튼 앞에 뜻이 분명한 아이콘을 둔다.
- **상태 표시**: 점과 짧은 상태어로 진행 상태를 보인다.
- **값 자체**: 100점 만점에 60점처럼 단위와 기준을 값에 붙인다.

## 8. 말투

- 평서형으로 끝낸다. 권하는 말투, 묻는 말투, 감탄을 쓰지 않는다.
- 괄호, 가운뎃점, 화살표, 느낌표, 이모지를 쓰지 않는다.
- 한 화면 안에서 말끝을 섞지 않는다. 한다체와 해요체가 같이 나오면 안 된다.
- 사용자를 부르지 않는다. 당신, 여러분, 님 같은 말을 넣지 않는다.
- 서비스가 자기를 소개하지 않는다. 저희는, 우리 서비스는 같은 말은 소개 화면에만 쓴다.

## 9. 검수 순서

화면을 다 만든 뒤 아래 순서로 한 번 훑는다.

1. 화면의 글자를 전부 뽑아 목록으로 만든다.
2. 각 줄을 이름, 값, 버튼, 오류, 고지, 설명으로 나눈다.
3. 설명으로 나뉜 줄은 3장의 표에서 둘 수 있는 자리인지 본다. 아니면 지운다.
4. 이름으로 나뉜 줄이 여덟 글자를 넘으면 6장의 방법으로 줄인다.
5. 값의 자리에 문장이 있으면 상태어로 바꾼다.
6. 같은 뜻의 말이 화면마다 다르게 쓰였는지 본다.
7. 지운 뒤 빈 껍데기 요소와 쓰지 않는 스타일이 남았는지 본다.

코드에서 찾을 때는 아래 낱말을 먼저 찾아본다. 대부분 지울 문구에 들어 있다.

```
하면, 할 때마다, 수 있다, 해 보자, 눌러, 클릭, 아직, 여기에, 표시된다, 자동으로, 한눈에, 간편, 손쉽게, 준비 중, 예시, 참고
```

## 10. 하지 말 것

- 제목마다 부제를 붙이지 않는다.
- 카드 제목 옆에 회색 꼬리표를 달지 않는다.
- 입력 칸 아래에 도움말 문장을 깔지 않는다. 형식이 정해져 있으면 칸 안의 예시 값으로 보인다.
- 기능이 어떻게 동작하는지 화면에 적지 않는다.
- 지운 문구를 툴팁으로 옮기지 않는다. 툴팁은 아이콘만 있는 버튼의 이름에만 쓴다.
- 문구를 지운 자리에 다른 문구를 채우지 않는다. 빈 자리는 그대로 둔다.
